# Восстановление Angular 15.2.1 / Webpack

Восстановлен доступный скомпилированный код из четырёх переданных файлов. Это не исходный Angular CLI проект: оригинальные TypeScript-типы, имена файлов, SCSS, комментарии, конфигурация и удалённый оптимизатором код отсутствуют. Никакие запросы к серверам приложения не выполнялись.

## Что находится в папке

- `original/` — неизменённые входные файлы, имена назначены по роли.
- `modules/` — 885 выделенных Webpack-фабрик. Это основной полный результат разделения. Русские строковые литералы декодированы. Числовые ID и сокращённые имена сохранены для точности.
- `index.json` — зависимости, алиасы импортов, экспорты и каталог компонентов. Все обнаруженные прямые числовые require-зависимости присутствуют. Это не означает наличия всех динамических чанков.
- `components/` — 423 определения компонентов приложения и библиотек; метаданные, извлечённые классы там, где удалось сопоставить их статически, и CSS. Ivy-шаблоны сохранены в `definition.js`. Идентификаторы в отдельных выдержках требуют контекста соответствующего файла из `modules/`.
- `components.csv` — каталог для поиска по селекторам.
- `operations/` — отдельно выделенный раздел операций: два класса компонентов, сервис, модель данных, работа с чек-листом, константы и все локальные функции шаблонов в `ivy/`. Имена классов назначены при реконструкции. Методы оставлены без исправлений поведения.
- `operations/operation-list.component.html` — вручную восстановленный эквивалент шаблона списка для обычного и планшетного экранов.
- `operations/module.factory.js` — полный связный контекст раздела операций, включая импорты и Angular-метаданные. Отдельные классы являются выдержками для изучения, а не автономными ES-модулями.
- `rebuilt/` — бандлы, собранные обратно из выделенных фабрик.
- `verification.json`, `rebuild-verification.json` — результаты проверки парсинга, исходные SHA-256 и сравнение AST после обратной сборки.

## Как работать

Найдите селектор в `components.csv`, откройте соответствующее определение и модуль. В `index.json` можно проследить, на какой модуль указывает сокращённый импорт. `operations/imports.json` содержит отдельную карту раздела операций.

Редактировать для обратной сборки нужно `modules/<ID>.js`. Выдержки в `components/` и `operations/` не подключены к сборке автоматически.

```powershell
node tools/rebuild.cjs
```

Команда сравнивает нормализованные AST: к оригиналу и результату применяется один генератор Babel; игнорируются комментарии, позиции, запись литералов, эквивалентные скобки вложенных if и группировка одинаковых логических операторов. После намеренных изменений кода несовпадение ожидаемо и возвращается код завершения 1; бандлы при этом сохраняются. Имена в `rebuilt/` условные: исходные серверные имена с хешами необходимо брать из runtime/HTML сайта.

Повторное извлечение из исходных вложений (перезаписывает результаты):

```powershell
npm ci --prefix tools
node tools/recover.cjs
```

## Что не восстановлено

Полные исходные HTML-шаблоны остальных компонентов не реконструированы: сохранён их точный скомпилированный код. CSS остаётся с Angular-маркерами `_ngcontent-%COMP%`, без попытки выдать его за исходный SCSS. Нет исходного `angular.json`, `package.json` приложения, статических ресурсов, HTML страницы и остальных ленивых чанков. Поэтому запуск всего приложения и его работа с backend не проверены; `ng serve` в этой папке не предусмотрен. Синтаксическая эквивалентность не заменяет проверку интерфейса.
